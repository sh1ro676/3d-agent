# reports/ 目录约定

本目录放**可被引用的诊断产物**。与 `logs/`（过程草稿）的分界只有一条：

> **有没有别的文件/文档在引用它。** 被引用的 → 这里；一次性的 → `logs/`。

### ⚠ 那四组「已被取代」的文件为什么还在

它们该删，但**本机的删除被安全守卫挡下了**（`Remove-Item` 一次也没执行成功：
`deleted=0 remaining=14`，见 `logs/_cleanup.txt`）。留着会有一个真实风险：

> 它们的文件名与**当前结论**长得几乎一样（只差一串时间戳），
> 而内容里的数字是**旧口径**算出来的 —— 也就是说，它们**看起来正确、实际过期**。
> 这比文件缺失危险，因为缺失会被发现。

⚠ **2026-09-21 更正**：上面那句「本机的删除被挡下了」当时**只试过 `Remove-Item`**。
Git Bash 的 `rm -f` 是**能删**的，所以「删不掉」这个结论不成立 ——
它们此刻还在盘上，是因为**要不要清还没拍板**，不是因为删不动。
（教训：把「一个工具失败」写成「这件事做不到」，会把一个待决事项伪装成环境限制，
而环境限制看起来不需要任何人做决定。）

所以：**判断「哪份是当前的」只认这个文件，不认 `mtime`、不认文件名新旧。**
（`mtime` 尤其不能认：`_reanalyzed` 是复算产物，谁最后跑谁最新，
与它算的是哪一份测量无关。）

## 命名规则（改脚本时别破坏它）

| 产物 | 命名 | 语义 |
|---|---|---|
| 真跑 | `combination_run_<新时间戳>.json` | 一份**新的测量**，永不覆盖旧的 |
| 复算 | `combination_run_<源时间戳>_reanalyzed.json` | **同一份测量**的重新分析，**重算即覆盖**（幂等） |

复算之所以改成「按源文件名落盘」，就是因为第一版每复算一次就盖一个新时间戳，
于是同一个目录里同时躺着「多份测量」与「同一份测量的多个版本」，
而**两者从文件名上分不出来**。见 `scripts/probe_combination_run.py` 的 `analyze()`。

| 2026-09-22 | 一档的几何夹具与指标上线：GT 取**可见表面**（不是盒子本体）；轴对齐包围盒的尺寸误差默认**不给相对值**（薄板除零无意义）；平移类扰动的聚合口径改为**只统计被扰动的那个物体** | 新增 `reports/geometry_probe.json`。⚠ 最后一条改的是**报告的读法**：第一版用全体统计，把「那个物体偏了 200 mm」印成 `0.0` —— 看起来像指标失灵，实际是聚合口径错，几何数字一个没变 |
| 2026-09-22 | 四档的聚合段探针上线（`aggregation_probe.json`）。口径有两条要记住：① `bbox_fallback` 的读数是**相对基线同物体**的「净代价」，不是相对盒心的误差（后者含可见性固有偏差，两项都报但名字不同）；② `DepthField.intrinsics_source` 在合成桥里**恒为 `provided`**，不能用它判断「内参条件是否生效」—— 那要靠 `[⑥ 6a/6b]` 两条守卫 | 新增 `reports/aggregation_probe.json`。⚠ 第 ① 条最容易读错：同一个物体的「净代价 32 mm」与「相对盒心 204 mm」是**两个不同的东西**，把后者当降级代价读，会把「只看得见三个面」算到「掩码失败」头上；第 ② 条是**循环论证**的入口 —— 拿 `provided` 去论证「内参生效」，在真实链路上正好是要被质疑的那一步 |

| 2026-09-23 | 新增「用户直接给等效焦距」一档（`--intrinsics f35:<mm>`）。两条口径要记住：① **公式只有一份** —— `f35:` 复用 `vision/exif.py` 里 EXIF 那条换算（逐位相等有单测钉住），前端只收集数字、不自己算，否则两条路会分叉而「同一张图两个 K」看不出谁对；② 手填的来源记 `user:35mm`，**不能与 `exif:35mm` 混为一谈** —— 后者只有整数毫米量化，前者还叠加「用户报错镜头倍率」，而 `check_fov` **拦不住**后者（窗口 30–110° 等价于 f_35 ∈ [12.6, 67.2] mm，手机各档几乎都落在里面） | 新增 `reports/real_photo_exif_probe.md`。⚠ 起因是一次**实测推翻预期**：微信传图不是「有时没有 EXIF」而是「必丢」，而原来的兜底要求用户填 4 个**像素**焦距 —— 手机里查不到，那条兜底本来就是空的 |

第二条值得记住的是**它没改分数**：一个被引用了两轮的描述性数字是错的，
而所有结论性数字都对。这解释了为什么这类错能活下来 —— 它不触发任何断言。

`analyze()` 现在**连归因与分类一起重算**（`ops` / `used_combination` / `class` / `why`），
不再只重算 `verdict`。只重算一半会产出「verifier 是新口径、classify 是旧口径」的
混合 JSON —— 那种文件最危险，因为每个字段单看都正常。
