# 臂 E′（多轮 tool-calling）协议与观察预算

> **S1：只定协议，不写代码。** 本文是实现的**唯一依据**——代码与本文不一致时，
> 要么改代码，要么**先改本文**（不许"实现时顺手调一下"）。
> 前置：`docs/臂E-prime实现代价估算.md`；主路径口径：方案文档 §13.3。

---

## 0. 一句话

**一轮 = 一个动作 + 一次观察。** 模型不再一次性写出整条工具序列，
而是每轮只决定**下一个**动作，看到结果后再决定下一步。

这正是 E′ 与主路径的**唯一差异**——所以本文的每一处规定，目的都是
**让这个差异可言、可比、可证伪**，而不是让 E′ 跑起来。

---

## 1. 协议选型：文本动作，**不用**原生 function-calling

**决策**：模型输出一个 JSON 动作块（文本），循环层解析并执行。

三条理由，按重要性排：

1. **不加接口分叉。** `LLMClient.chat()` 的 payload 只有
   `model / messages / temperature / max_tokens` +（静态的）`extra_body`
   （`llm/adapter.py:524-537`）。用原生 tool-calling 就得给 `chat()` 加一个
   **按调用传参**的 `tools=` 通道 ⟹ 所有既有调用方都要多一个可选参数，
   而它们的语义并没有变。
2. **校验必须只有一套。** 主路径的护栏长在**文本**上：AST 静态检查、显式工具白名单
   （`QA_TOOLSET`）、六种错误码。换成服务端 JSON-schema 校验，两条臂就各有各的
   合法性判据 —— 那正是"消融里混进了第二个变量"。
3. **不押注 4B 级模型的原生支持。** 服务端 function-calling 的稳定性随模型/版本变，
   而文本 JSON 的解析失败**是我们能看见、能记账、能重试**的一类失败。

**代价（如实记）**：文本协议要靠提示词约束格式，遵守率是**要测的量**（见 §10-1），
不能假定。主路径已有的 `extract_code`（`agents/synthesizer.py:284`）正是为
"模型没按格式给"留的观测点，E′ 沿用同一形态。

## 2. 消息布局

system **逐字节与前缀稳定**（工具文档同源，见 §9），历史**逐轮累积**：

```
[0] system  = SYSTEM_TEMPLATE(system) + docs_text(QA_TOOLSET) + LOOP_PROTOCOL
[1] user    = 首轮：问题 + scene_hint + answer_type + 动作语法说明
[2] assistant = 第 1 轮动作（JSON）
[3] user      = 第 1 轮观察
[4] assistant = 第 2 轮动作
[5] user      = 第 2 轮观察
...
```

规则：

- **动作与观察都进历史**（`role="assistant"` / `role="user"`）。不重写、不折叠 ——
  折叠历史会让"模型看到了什么"不可复核。
- 首轮消息里**不预先列出场景物体**：那等于把 `list_objects` 白送，会掩盖
  "E′ 因为先检索而占优"这一条本来想测的机制。
- 与主路径一样：**工具文档进 system**（逐字节稳定 → 服务端前缀缓存才可能命中，
  §7 要测它）。

## 3. 动作语法（模型 → 系统）

回复里**恰好一个** fenced ```json 块，内容是单个对象。两种动作：

```json
{"action": "call", "tool": "find_nearest", "args": {"anchor": "door", "label": "chair", "k": 2}}
```

```json
{"action": "submit", "answer": 1.42, "target_ids": ["chair_2"], "evidence": ["chair_2"]}
```

约定：

| 项 | 规定 |
|---|---|
| 动作数 | **每轮恰好一个** `call` 或 `submit`。一轮多个 `call` 会稀释"逐步决策"的含义（**若将来要放开，必须先改本文并重跑对照**） |
| 工具名 | 必须在 `QA_TOOLSET` 之内（12 个）。越界 ⟹ 协议违规（不是"参数错"） |
| 参数名 | 必须在该工具 `__signature__` 之内（`llm.schema.params_of`）。越界 ⟹ 协议违规 |
| `submit.evidence` | **≥1 条**（`_SubmitBox` 硬校验，`agents/executor.py:429`）。越界的 id 进 `unknown_targets`（复用 `Submission.unknown_targets`，**不是错误**） |
| 弃答 | ⚠ **不要发明 `abstained` 字段**。现有契约的弃答是**由答案本身判定**的：`answer` 落在 `ABSTAIN_TOKENS`（`{"unknown", "abstain", "cannot_answer", "n/a"}`）里 ⟹ `abstained=True`（`agents/executor.py:74,435`）。所以 E′ 写 `{"action":"submit","answer":"unknown","evidence":["没有找到门"]}` 即可 —— 自造一个开关等于**两条臂各有一套弃答判据**，正是 §3 要避免的那件事 |
| 解析失败 | 没有 fenced 块 / 不是合法 JSON / 缺 `action` ⟹ **协议违规**，一句话说明哪里不对后回灌，计数 +1 |

复用：`Submission` / `_to_number` / `_normalize_list` / `_SubmitBox`
（`agents/executor.py:164,475,498`）**原样使用**，不在 E′ 里另写一套 ——
否则"弃答判定"两条臂不一致，比较就废了。

## 4. 观察格式（系统 → 模型）

观察 = **一次工具调用结果的裁剪版**，结构固定：

```json
{"round": 2, "tool": "find_nearest", "ok": true,
 "value": [{"object_id": "chair_2", "label": "chair", "distance_m": 1.4221854777889445,
            "centroid_m": [0.512, -0.301, 1.884]}],
 "ids": ["chair_1", "chair_2"],
 "n_total": 3, "n_shown": 1, "elided": 2,
 "note": "已省略 2 项；需要全部请调大 limit="}
```

失败时：

```json
{"round": 2, "tool": "single_object", "ok": false,
 "error": {"code": "AMBIGUOUS", "message": "匹配到 3 个 chair，请用 object_id 指定"},
 "ids": ["chair_1", "chair_2", "chair_3"]}
```

**五条硬规则**：

1. **必须带 `ok`**，失败必须带 `error.code`。信封（`ToolResult`）就是为
   "让失败可见"存在的，裁掉它等于让模型对失败一无所知。
2. **`ids` 必带，且含被省略项的 id**。它是模型的**证据词汇表**
   （§3 的 `evidence` 只能取自这里），也是"模型有没有幻觉 id"的观测点。
3. ⚠ **数字原样保留，不做四舍五入。** 观察是**证据**，不是展示；
   舍入会让模型提交一个与工具真值不一致的数，
   然后被 `agents/verifier.py` 判成 `unsupported` ——
   **那是尺子错，不是模型错**。（若将来真要舍入，必须把**同一份舍入值**同时喂给校验器。）
4. **裁剪只发生在循环层**，工具层照旧返回全量。裁剪必须**显式声明**
   （`n_total` / `n_shown` / `elided`），否则"模型没看到"会伪装成"模型不会"。
5. `centroid_m` 等长数组按**位**截断到 `OBS_BUDGET`，**截在数组中间要标记**，
   不许静默丢尾巴。

## 5. 终止条件与状态映射

**不新增 `STATUSES` 取值**（`agents/loop.py:73` 的五个值是 metrics 口径的一部分，
加值必须同时改口径）。终止因落在 `stages` 的 `stage` 上：

| 终止因 | `status` | 额外记录 |
|---|---|---|
| 合法 `submit` | `ok` / `abstained`（按 `submission.abstained`） | — |
| 达到 `max_rounds` | `exec_failed` | `stage="budget_exhausted"` + 最后一轮动作 |
| 协议违规超限 | `exec_failed` | `stage="protocol_violation"` + 违规计数 |
| LLM/传输失败 | `llm_error` | 沿用现有路径 |
| 工具执行失败 | **不终止**，作为观察回灌继续 | 失败次数计入 trace |

**"工具失败不终止"是刻意的**：E′ 的机制价值就在于"错了还能改"。
把工具失败当成终止，等于把 E′ 的容错优势提前砍掉，再和主路径比 —— 那是不公平的比较。

## 6. 预算：四个常数必须显式

四个都必须是**构造参数**（默认值写死在这里），并且**全部进产物**——
"没写就是默认"会让两次不同预算的实验在记录里长得一模一样。

| 常数 | 默认 | 为什么是它 |
|---|---|---|
| `max_rounds` | **4** | 主路径每题中位工具调用 2；留一倍余量。超过 4 轮的收益须先证 |
| `OBS_BUDGET`（观察上限 tokens） | **320** | 12 个工具里最长的 `value` 是物体列表；320 ≈ 见 §4 示例 3–4 项 |
| `max_protocol_violations` | **2** | 同主路径 `max_synthesis_retries=2` 的口径（显式常数，便于复现） |
| 单轮 `timeout_s` | 沿用 `LLMSettings.timeout` | 不另立一套超时口径 |

**成本投影**（`B` = 1549 = 实测单轮 prompt；`A` = 80 = 动作 JSON 的 completion 估计；
`O` = 320）：

```
第 k 轮 prompt = B + (k-1)·(A + O)
N 轮合计       = N·B + (A+O)·N·(N-1)/2
```

| N | prompt 合计 | 相对单轮 | 墙钟（1.46 s/轮） |
|---|---|---|---|
| 1（＝主路径） | 1 549 | 1.0× | 1.5 s |
| 3 | 5 847 | **3.8×** | 4.4 s |
| 4 | 8 596 | **5.5×** | 5.8 s |
| 6 | 15 294 | **9.9×** | 8.8 s |

> ⚠ 本表**取代** `docs/臂E-prime实现代价估算.md` §4 的粗算（那里只算用户的观察、
> 没算 assistant 的动作，且用 `A`=300 当动作长度）。两处的差别本身也是记录：
> **估算的第一版漏了一项**。

⚠ 若服务端前缀缓存生效，计费增量只落在**增长的尾巴**上，真实倍数会显著低于本表。
S0 已把这件事变成**可测**（`cached_tokens` / `cache_source` / `usage_keys`）——
**先跑一次真调用看 `usage_keys`，再决定要不要为"缓存不命中"预留预算。**

> ✅ **已实测（2026-09-21），本表的上界地位被确认，数值需下修。** 两次真跑（`living_room`，同一问题）：
> `prompt_tokens` 1 934，`cached_tokens` **1 664（86.0%）→ 1 792（92.7%）**，
> `cache_source=prompt_tokens_details.cached_tokens`。
> ⭐ 并且找到了**零成本预测口径**：前缀缓存按前缀匹配、system 永远在最前 ⟹
> **命中率天花板 = system 占整条 prompt 的比例**，用 `--dry-run` 读 `system_prompt_chars`(4 016) /
> `msg_digest.text_chars`(4 299) 即可算出 = **93.4%**，与实测 92.7% 吻合。
>
> 代入本表公式（逐轮只有新增的 A+O=400 是 miss）：**4 轮 prompt 合计 10 136、命中 8 794（86.8%）** ⟹
> 账本口径 **≈3.3×**；若缓存折扣按 1/10（**未在本项目验证**）则 **≈1.8×**。
> ⚠ 因此 **5.5× 应读作"上界"，不是预期值**。完整推导见
> `docs/臂E-prime实现代价估算.md` §4b。

## 7. 记账：三样东西必须分开，不能混

| 量 | 记在哪 | 混掉的后果 |
|---|---|---|
| LLM 成本 | `usage.by_purpose["tool_loop"]` | 与主路径的 `synthesize` 混在一起，就算不出"多轮贵多少" |
| **协议违规次数** | 独立的计数器 | 与主路径的 synthesis 重试混为一谈 ⟹ 分不清"模型不会用协议"和"程序写错了" |
| **观察被裁剪的次数 / 省略项数** | 独立计数器 | ⟹ 分不清**"模型不会"**和**"模型没看到"**（这正是 §14 教训 2，本项目栽过两次） |

⚠ 失败的调用**也要记耗时**（S0 已支持：`failed_latency_s`）——
"跑了 24 秒却记 calls=0"这种记录会让预算系统性偏小。

## 8. 可比指标：只有一条

**能比的只有端到端正确率**（`evaluation/metrics.py` 的口径）。
`Total = Σ(子指标 × 该类题数) / 501`，与主路径**同一函数、同一批次、同一模型**。

**不可放进同一张表的**（分母不同，放在一起就是错的）：

| 量 | 为什么不能比 |
|---|---|
| 「工具选择准确率」 | 主路径**一次选定整条序列**，E′ **逐步选** —— 分母不同。⚠ 而且该指标**目前没实现**（见估算文档 §5 前置 2） |
| 平均工具调用数、平均轮数 | 两条臂的动作粒度不同，不是同一单位 |
| prompt tokens、墙钟 | 这是**代价**，是结论的限定条件，不是成绩 |

## 9. 消融纯度：必须逐条对齐

1. **工具文档逐字节相同** —— 两条臂都用 `docs_text(QA_TOOLSET)`，
   heading 也相同。差一个字符，缓存前缀就断，成本差异里就混进了提示词差异。
2. `planner` 两条臂**同为 `"off"`**（臂 G 是另一个维度，别叠在一起）。
3. 同一批题、同一 seed、同一模型与温度、同一 `toolset`。
4. `answer_type` 逐题相同。
5. E′ 内部的协议违规重试**不计入** `max_synthesis_retries`
   （那是主路径的常数，含义不同）。

## 10. S2 的失败判据（**先写下来，免得事后找解释**）

S2 = 两轮最小版（一次检索 → 一次作答，≈120 行）。它要回答的是
**"4B 级模型守不守得住这套协议"**。三条判据，任一成立即停 S3：

1. **协议遵守率**：若 ≥1/3 的题在**第一轮**就发不出可解析的动作 ⟹
   协议对 4B 级模型过细 ⟹ 退到更粗的形态（例如一行
   `工具名 {参数JSON}`，去掉 fenced 与 `action` 字段），**而不是加更多提示词**。
2. **观察是否改变决策**：若"本轮动作签名 == 上一轮动作签名"的比例 ≥1/3 ⟹
   **"观察回流改变决策"这个机制假设不成立**，E′ 的结构性优势是空的。
   这是一条**否定性结论，同样要写进报告**。
3. **代价-收益**：若平均轮数 ≥4 且正确率相对主路径提升 ≤1 个百分点，
   而 prompt tokens ≥4× ⟹ 停，结论是"单轮规划在本任务上够用"。

> 判据 2 是这次最该被验的一条：主路径**必须盲猜工具序列**，
> E′ 可以先看一眼再决定 —— 优势**应该**体现在这里。
> 如果实测不体现，那说明优势是想象的。

## 11. 留给实现的开口（本文不定的）

- **`submit.evidence` 是否要求"取自观察过的 id"**。当前**不加**这条约束 ——
  现有契约只校验 `target_ids` 是否存在于场景（`known_ids`）。
  "必须在观察里见过"是**更严的新机制**：它能多抓一类幻觉（id 存在但模型没见过），
  但会偏离"原样复用契约"。**若要加，先改本文并说明它算不算失败。**
- 观察里是否携带 `evidence` 原始字段（当前决定**不带**，只带 `ids`）。
- `submit.evidence` 的长度下限是否要 >1（当前与主路径一致，为 1）。
- 是否允许 `call` 带 `limit=` 之外的"翻页"语义（当前无翻页，靠调大 `limit=`）。
- 多轮历史超过 `max_rounds` 后是否需要截断策略（当前不需要：4 轮就到顶）。

这五条都不影响 S2 开工；**真要做，先改本文**。
